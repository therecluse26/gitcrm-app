ChatGPT drafted the original entries. The owner reviewed every entry on 2026-10-27; the statuses below record those decisions.

| ADR-019 | accepted | Pipeline stages are editable in the MVP: rename, reorder, add, and remove when unused. `won` and `lost` always exist. Stage IDs never change | Owner decision 2026-10-27. Edits touch only `.gitcrm/workspace.json`, so no record migration is needed |
| ADR-020 | accepted | Typed custom fields ship first after the MVP. | ADR-021 | accepted | Delete cascades in one commit: tasks and activities related to the record are deleted; contacts, companies, and opportunities that link to it are unlinked, never deleted. Archived records count. A preview lists every change first. Uses the Git Trees/Commits APIs with a non-forced ref update | Owner decision 2026-10-27. One commit instead of one per link; no dangling links; removes notes about the deleted record from `main`. S-02: the Git Trees/Commits path works with a PAT that has only Contents, and GitHub refuses a non-forced ref update after `main` moved (`422`) |
| ADR-022 | accepted | First-load transport: chunked GraphQL tree walk pinned to one commit, about 100 files per query (from the recursive tree), up to 10 queries in parallel. GraphQL time budget: at most 50 s of summed response time per rolling 60 s, then wait. Per-blob REST only for small syncs. Do not build the verified rollup at the target scale | Owner decision 2026-10-28. Spike S-04, 2026-10-27/28: 2,000 records in 5–9 s vs 48 s per-blob; ~47 s of GraphQL response time, near GitHub's limit of 60 s per minute (S-05); a single large query fails with 502 after ~10 s, and timeouts cost extra points |
| ADR-023 | accepted | Rate-limit budget guard and one syncing tab: below 500 remaining REST requests, pause background checks; honor `retry-after`; one tab per workspace (chosen with Web Locks) checks `main` and shares results over `BroadcastChannel` | Owner decision 2026-10-28. Keeps normal use at a few percent of the hourly budget, and stops a runaway loop or many open tabs from exhausting it. A page can read `x-ratelimit-reset` and `retry-after` (S-01 addendum, 2026-10-31) |
| ADR-024 | superseded | Replaced by ADR-025 on 2026-10-31. Deployment: a GitHub Actions workflow deploys each push to `main` to the official copy, `gitcrm.pages.dev`. A build job with no secrets runs every check and builds once. A deploy job with only the Cloudflare token uploads that same build with wrangler, installed from its own lockfile, then checks the live site. No live copy on GitHub Pages: a browser test serves the same build from `/GitCRM/` with no custom headers instead. Until the public release, the official copy sends `X-Robots-Tag: noindex` | Owner decision 2026-10-31. Every deploy waits for every test, and the deployed build is the tested one. The token can replace the page where users type their PAT, so no project code or test dependency runs in the job that has it. GitHub Pages needs a paid plan for a private repo, its site is public anyway, and GitHub says Pages sites shouldn't take passwords (R-03). A second copy would also split each user's PAT and cache between two origins. Spec 09 |
| ADR-025 | accepted | Distribution: GitCRM is a GitHub template repository, with no central copy. Each owner makes an app repository from it; public is fine, because it holds no data. Its workflow deploys the app to that repository's GitHub Pages with no secrets, after the owner turns on Pages once (Settings → Pages → Source: "GitHub Actions"). CRM data lives in a separate private data repository, and the PAT reaches only that repository. The template repository itself never deploys. `gitcrm.pages.dev` is taken down | Owner decision 2026-10-31, after the first run against a real repository. A central copy makes every user trust whoever deploys it, because each visit runs the code it serves. Each owner now runs code from their own repository. Two repositories keep Pages free on GitHub Free (Pages in a private repository needs Pro or Team, S-05), and a leaked PAT cannot change the app. The workflow cannot turn on Pages: `actions/configure-pages` needs a token other than `GITHUB_TOKEN` for that (S-09). Sign-in without a PAT still needs a server (ADR-009). Replaces ADR-024. Spec 09 |
| ADR-026 | accepted | Template updates: a scheduled workflow in each copy opens a pull request when the template has a new release. The owner reviews and merges it | Owner decision 2026-10-31. A repository made from a template has no link back to the template, so fixes never reach copies on their own. Updating the app is a software task, which ADR-006 allows. The workflow's own token cannot change files in `.github/workflows/`, so an update to a workflow needs one manual step. When Actions may not open pull requests in a copy (GitHub's default), the workflow opens an issue that links to the pull request. The template must be public, so a copy's token can read its releases. Spec 11 |

## Decision process

For changes to a product invariant: state the requirement, propose at least one solution with **no new runtime infrastructure**, show consequences for export/ownership, explain alternatives, then update this log. Implementation shortcuts do not override product decisions.
